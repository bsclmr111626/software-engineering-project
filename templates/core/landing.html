The problem

Software is assembled from many hands. Each one is a way in.

Code, dependencies, build automation and deployment credentials are owned by different people and tools. A weakness early in the chain is inherited by every stage after it, so protecting production alone leaves most of the path undefended.

01

Inherited trust

A compromised developer account or a poisoned dependency arrives already trusted by the stages downstream.

02

Automation holds the keys

Pipelines and registries carry the credentials needed to publish and deploy, which makes them high-value stepping stones.

03

Controls are hard to compare

Teams rarely see which control actually removes the most risk for a given attack, so effort goes where it is easiest, not where it counts.

Capabilities

From a threat scenario to a remediation plan, with every step on the record.

Everything below is part of CodeGuard today. Nothing is estimated by an opaque model: each number comes from formulas you can read in the methodology.

Threat library

Reference attack scenarios with entry points, propagation rules, assumptions and business impact. Clone them or write your own private scenarios.

Propagation simulation

A breadth-first walk of the scenario's rules through the five stages, deciding at every edge whether the compromise spreads, is blocked or stays below threshold.

Inherent and residual risk

Each run scores the chain with no controls and with your controls, per stage and overall, on a 0 to 100 scale with four risk classes.

Control recommendations

For every control you have not enabled, CodeGuard re-runs the scenario with it and ranks the exact modeled reduction.

Remediation tracking

Commit to a recommended control, set a due date and status, and see it verified when a later run includes the control.

Reports and audit trail

Every run keeps a versioned snapshot of its inputs, so reports never change. Exports, sharing and sign-ins are recorded in an append-only audit log.

How simulations work

Four steps, one deterministic rule set.

A run walks the scenario's propagation rules from its entry stage. Preventive controls lower the probability of each hop; an edge propagates only when what remains meets the threshold.

  1. Choose a scenario

    Pick an attack from the threat library. Its entry stage, likelihood, severity and impact are prefilled and adjustable for the run.

  2. Set the controls

    Enable the controls that exist in your environment. Each one protects specific stages with a documented, illustrative effectiveness.

  3. Propagate

    Each edge is evaluated once: effective probability = edge probability × (1 − preventive coverage). At or above the threshold, it spreads.

  4. Read the result

    See where it spread, which controls mattered, what each recommendation would remove, and compare runs before and after.
